## Defects fixed

- `registerScheduled(scheduler, structValue)` did not compile for any struct whose first field was not of the struct's own type. `new T(component)` is field-wise construction in D, not a copy. The value is now copied through a one-element array literal, which respects the struct's copy semantics. Exposed by row 34.
- `registerScheduled(scheduler, pointerVariable)` (an lvalue `S*`) resolved to the `ref T` overload with `T = S*` and failed to compile. The documented pointer form only worked with rvalues such as `new S(...)`. The `ref T` overload now forwards a struct pointer to the pointer overload. The signature is unchanged. Exposed by row 34.

## Notes and limitations

- `Scheduler.close` can wait for admitted jobs only from a separate reactor task on the owner thread. Anywhere else it cancels the children and returns `unavailable` (row 19). Reactor tasks are `@nogc` but `Scheduler.open` and `add` allocate, so a reactor-owned scheduler has to be opened on a reactor worker by startup code. The close-join test does this from a thread-local module constructor that runs only while the test is armed.
- Day-of-month and day-of-week count as "restricted" when their bit mask does not cover every value. A field such as `0-6` therefore behaves like `*` (AND semantics). Vixie cron instead tests for a leading `*`.
- `cancel` returns `ok` for unknown or stale IDs. This is the idempotent behaviour the spec asks for.
