# flint:rpc acceptance traceability

Source: `handoff/specs/tier-2/rpc.md` section 7 ("Required unit, protocol, fuzz and benchmark acceptance"; this spec numbers the acceptance table 7, not 6) and the observable semantics in section 4. Unit tests run with `dub test :rpc` on DMD and LDC. The protobuf tests need the nested `FLINT RPC TEST NATIVE` recipe block, which links the checked `flint_rpc_fixture` codec. Unnamed unittests are cited by their line.

Fixture commands (all run on 2026-11-21 against both compilers):

- `<lb>` is `fixtures/loopback/app.d`, built with `-version=FlintNativeLlhttp -version=FlintNativeNghttp2 -version=FlintNativeOpenssl -i=flint` and linked against `libflint_ffi.a`, llhttp, nghttp2, OpenSSL and protobuf-c.
- `check_http1.py <lb>`: independent WebSocket and SSE clients.
- `check_http2.py <lb>`: hyper-h2 client with a 4096-byte stream window.
- `grpc-go-loopback 127.0.0.1:<port> echo.desc [--bench]`: `fixtures/grpc-go`, gRPC-Go v1.76.0 with its standard Protobuf codec, run against `<lb> <port> h2`.
- `check_grpc.py grpc-go-server echo.desc <grpc> cert key`: `fixtures/grpc-go/server` peer against the outbound client `fixtures/outbound/grpc.d`, over loopback h2c and over TLS with ALPN h2.
- `check_realtime.py <realtime> cert key`: outbound SSE and WebSocket clients, cleartext and TLS.
- `check_flow.py <flow>`: HTTP/2 stream credit with reads paused.
- Autobahn Testsuite 25.10.1: `wstest --mode fuzzingclient` against `<lb> <port> h1`, and `check_autobahn.py <realtime>` with Flint as the client. Both exclude groups 9, 12 and 13, following the upstream sample.
- `negative/run.py dmd ldc2 --protobuf-prefix <protobuf-c install> --scratch <dir>`: compile-fail fixtures in debug and release, plus rejected generator schemas.
- `tools/protoc-gen-flint ... --schema tests/proto/echo.proto --output tests/generated --check`: regeneration diff.

## Findings (not fixed here)

- F1 (ignored input). `StreamLimits.queuedMessages` and `StreamLimits.queuedBytes` are range-checked in `registerGrpc` but never read afterwards. Each `RpcStream.send` copies one message into the transport and yields until it is accepted. The effective bound is therefore one message in flight per stream plus the web connection's `writeQueueBytes` (default 256 KiB). That is within the spec's 16-message / 1 MiB ceiling, but a smaller configured value has no effect. Enforcing it needs a per-stream queue bound in `flint:web`'s stream API.
- F2 (`flint:web` HTTP/2 server, outside this package). When a server ends a gRPC call (trailers, END_STREAM) while the client's upload is still open, `GrpcCall.receive` does not see the end until the caller's own deadline. Example: early `UNIMPLEMENTED` or a status sent before reading. Observed in-process: the server's `Status` action finished immediately, but a client that had not called `finishSend` got `timedOut` after 3 s. The client transport cannot detect this case: the pinned libcurl keeps END_STREAM and the trailers of a half-closed HTTP/2 stream until the stream closes in both directions (see `packages/http/ACCEPTANCE.md`, "duplex early end"). It closes promptly when the server follows RFC 9113 section 8.1 and sends RST_STREAM(NO_ERROR) after its complete response, as grpc-go and net/http do. `native/ffi/flint_web.c` does not, so the tests here call `finishSend` first. A server-side change that sends RST_STREAM(NO_ERROR) from the nghttp2 frame-send callback when END_STREAM leaves the request side open makes the in-process calls finish without `finishSend`; it needs the `flint:web` owner.
- No stub or always-success paths were found in `source/`. The `Error.init` returns follow completed native calls or idempotent closes.
