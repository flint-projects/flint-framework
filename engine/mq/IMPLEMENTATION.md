# Kafka and JetStream

`QueueClient.open` validates startup options and sets up an owner-confined client. Bind it on its first publish or poll and perform subsequent operations on that Reactor owner's fibers or the same standalone thread. A publish returns only after the broker sends its receipt. Cancellation or a timeout after admission can leave the outcome ambiguous. Application retry requires an idempotency policy.

Kafka uses a dedicated native librdkafka polling thread. Publish data is copied once into owned native storage. The provider releases it only when the delivery report resolves. The bridge enforces the configured byte limit across queued publishes and delivery arenas, and preallocates fixed receipt and assignment tables. Producer policy enables idempotence and requires `acks=all`. Use a comma-separated bootstrap list for plaintext or prefix it with `ssl://` for TLS. TLS verifies peer trust and hostname and accepts an optional CA bundle.

The consumer disables automatic commits and offset storage. Each partition advances only past its confirmed delivery-order prefix. A retry holds the prefix and redelivers with a new token. A rebalance retires the old assignment while keeping any currently borrowed delivery bytes live until the handler returns. An acknowledgement with a retired generation cannot commit into a fresh assignment. A successful dead-letter receipt is required before handling a rejected delivery as complete.

JetStream connects to `nats://HOST:PORT` or verified `tls://HOST:PORT`. Configure streams and explicit-ack durable pull consumers in the broker before subscribing. Each client serializes one outstanding pull or publish and requests one record when its delivery workspace is free. The parser caps both command lines and payloads, uses advertised byte counts for MSG and HMSG, and preserves CRLF inside payloads. NATS message ids request broker deduplication within the configured window. The optional `confirmedAcks` setting waits for the server reply to a positive acknowledgement. Retry sends a delayed negative acknowledgement, and reject publishes to the configured dead-letter subject before acknowledging the original. Application side effects still require idempotency or an outbox. A transport error or request timeout fails that request with `unavailable` (connection lost, outcome ambiguous) or `timedOut` and retires the socket. The next publish or poll reconnects automatically: the first attempt is immediate and failed attempts back off from 25 ms, doubling to at most 2 s, waiting only within the caller's deadline; otherwise the call returns `unavailable` at once. Registered pull consumers need no re-creation because their durable state is on the broker and every pull opens its own reply subscription. A delivery whose acknowledgement was lost with the connection is redelivered by the broker. `close` stops reconnection (ADR-017 decision 12).

`registerListeners` accepts a persistent class component annotated with `KafkaListener` or `StreamListener`. Its method can consume a raw `Message` or a JSON DTO, followed by the scoped arena and context. Methods must be `@safe nothrow @nogc` and return `AckAction`. Listener registration is a startup operation. A delivery arena's handles expire when its handler returns.

`drain` stops admission and observes the caller deadline while waiting for receipts and confirmed commits. `close` is idempotent and joins native work before freeing its storage. Each client accepts up to 1,024 in-flight slots, 16 MiB of owned queue and delivery bytes, and a delivery timeout of up to 15 minutes.

## Verification

Linux glibc tests use pinned librdkafka 2.16.0, Apache Kafka 4.1.2, and NATS 2.15.3. The live scenarios cover producer receipts, retry and stale-token rejection while a real Kafka rebalance revokes an active delivery. The offset fixture completes 10, 12, then 11 and observes commit progression 11, 11, then 13. The independent JetStream fixture checks the broker acknowledgement floor, deduplication, intentionally lost acknowledgements, delayed retries, typed decoding, verified TLS, and routing a rejected message into a separate stream. Two handling attempts inserted one SQLite row. The 600-second native outage held exactly 16 MiB of admitted payload and rejected additional publishes.

The matching local benchmark workload publishes 512 records for each combination of 256-byte or 8-KiB payloads and 1 or 16 partitions, using a single broker replica and `min.insync.replicas=1`. Both executables check a real provider receipt for each publish. Raw timing, hashes, queue outage observations and sanitizer logs are retained in `artifacts/tasks/m5-mq`. Fixed-runner performance certification and non-Linux qualification remain open.
